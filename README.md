# Pyctos (Python Concolic Testing Over SMT)

This is a program for concolic execution of python code.

## Installation

`python -m pip install .`

## Usage

The tool installs a `pyctos <path-to-function> [-f <function-under-test>]` command, which concolically executes a function to explore its paths (the so-called function-under-test, FUT).
The two positional parameters to `py-symbex` are:
- `<function-under-test>`: the local name of a FUT, such as "foo" for a top-level function or `Foo.bar` for a class method. The name is a period-separated sequence of identifiers as you might expect
- `<path-to-function>`: a path to the file containing the FUT, such as `examples/simple.py`

There are some additional flags we support. For example:

- `--smt [solver]`/`-s [solver]`: Select the SMT solver backend (`z3` and `cvc5` are supported with `cvc5` as the default)
- `--float`: Select the theory for modeling floating-point numbers in Python (`fp64`, `real`, and `exreal` are supported with `exreal` as the default)
- `--verbose`/`-v`: Enable verbose output


## Example usage

`pyctos -f Foo.foo examples/simple.py`

which produces: 

```
| INFO | Exploring Foo.foo
| INFO | Inputs for all paths:
| INFO | []Foo.foo(0, 0)
| INFO | []Foo.foo(1, None)
| INFO | []Foo.foo(1, 2)
| INFO | []Foo.foo(1, 0)
| INFO | []Foo.foo([0, None], None)
| INFO | No branches were left unturned!
```

The function under test is foo in [examples/simple.py](examples/simple.py), whose definition is:

```python
def foo(a: int, b: int) -> int:
  if a > 0:
    if b > 0:
      return a + b
    else:
      return 0
  else:
    return b
```

## Limitations

This technique currently models a subset of pure Python, excluding certain difficult types.
Items on the roadmap are:
- Modeling native code
- Better scalability for large, complex codes

# Pyctat (Python Coverage Testing Auxiliary Tool)

This is a program for doing coverage testing using the inputs generated by a Pyctos run.

## Usage

The tool installs a `pyctat <function-under-test> <path-to-function>` command, which performs coverage testing on a given function, loading inputs generated from Pyctos.

## Example usage

`pyctat Foo.foo examples/simple.py`

which produces:

```
| INFO | Testing Foo.foo
| INFO | Executed lines: 6
| INFO | Missing lines: 0
| INFO | Function coverage of Foo.foo: 100.0%
| INFO | Branch coverage of Foo.foo: 100.0%
| INFO | Inputs that raised an exception in the function: 2/5 (40.00%)
```

# Pyctest (Pyctos Coverage Test Suite)

This is a program for running the Pyctos test suite locally. It discovers functions
marked with `@pyctos_test`, dispatches Pyctos to generate replay inputs, and then
dispatches Pyctat to check that those inputs hit full coverage.

## Usage

The tool installs a `pyctest [path]` command, where `path` is a Python file or directory
to scan recursively for decorated tests. If no path is provided, it scans `examples`.

Tests are registered with the `@pyctos_test` decorator:

```python
from pyctest import pyctos_test


@pyctos_test('numpy.views', run_timeout=60000)
def transpose_read_scalar(x):
  ...
```

The test's `run_timeout` and `solver_timeout` are both specified in milliseconds.

Nested tags are expanded, so `numpy.views` registers both `numpy` and `numpy.views`.
Filtering is exact against the expanded tags: `-t numpy.views` runs only tests with
that nested tag, not all tests matching `numpy`.

Useful flags:

- `--list`: List discovered tests as `path::function` without running them
- `--list-tags`: List all discovered tags
- `--tag`/`-t`: Run tests with a tag; may be repeated, and comma-separated tags are allowed
- `--exclude-tag`/`-x`: Exclude tests with a tag; may be repeated, and comma-separated tags are allowed
- `--keyword`/`-k`: Run tests whose `path::function` id contains the given string
- `--num-workers`/`-n`: Run tests in parallel

Note that high worker counts can cause SMT solver instances to come back `unknown` more often; if tests are unexpectly failing with higher parallelism, try bumping the test's `solver_timeout`.

## Example usage

List all discovered tests:

`pyctest --list`

Run numpy view manipulation tests:

`pyctest -t numpy.views`

Run only transpose-related tests, in parallel:

`pyctest examples/numpy_examples/views.py -k transpose -n 4`
